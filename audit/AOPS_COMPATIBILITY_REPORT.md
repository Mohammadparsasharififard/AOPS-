## 9. Honest limitations

The audit found these hard limitations that CANNOT be overcome without
violating the project's core principle of never bypassing access controls:

1. **AoPS Community / Forum content**: Most threads/posts require login to view.
   Without bypassing login, MathVault cannot archive them. They will be
   recorded as `login_required` in the `blocked_url` table.

2. **CAPTCHA-protected pages**: Any page that returns a CAPTCHA challenge
   is recorded as `captcha` in `blocked_url` and the crawl continues.

3. **Paywalled content (AoPS Classes)**: Recorded as `paywall` in
   `blocked_url`.

4. **Rate-limited requests**: If AoPS returns 429, the URL is recorded as
   `rate_limited` and the crawl continues with `CRAWL_DELAY_SECONDS`
   (default 2 seconds, configurable).

5. **MediaWiki categories**: The crawler follows them as links (good) but does
   NOT currently parse the breadcrumb trail into the semantic Contest → Year
   → Problem hierarchy. The pages ARE archived; the structural metadata is
   not yet extracted. A small adapter (parsing only, no bypass) would fix this.

## 10. Proposed `sources/aops/` adapter layer

If you want AoPS-specific parsing (extracting the MediaWiki breadcrumb chain
into the Contest/Year/Problem schema), here is the proposed structure:

```
mathvault/
├── crawler/                    # Generic engine — unchanged
├── sources/                    # NEW — per-source adapters
│   ├── __init__.py
│   ├── generic/                 # Default — works for any allowlisted source
│   │   ├── __init__.py
│   │   └── adapter.py          # No-op adapter; uses crawler as-is
│   └── aops/                    # AoPS Wiki adapter
│       ├── __init__.py
│       ├── adapter.py           # Parses MediaWiki breadcrumbs → Contest/Year/Problem
│       └── README.md            # Explains what's covered + what's not
└── ...                         # rest unchanged
```

The adapter is a **PARSER ONLY** — it does NOT bypass CAPTCHA, login,
paywall, robots, rate-limit, or any other access control. If a piece of
AoPS content is access-protected, the adapter does nothing — the URL is
already recorded as BLOCKED by the generic crawler.
